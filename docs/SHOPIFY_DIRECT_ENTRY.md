# Shopify直接来店・LINEポイントカード連携

更新日: 2026-10-28。LINE認証を先に行う2パターンへ仕様を更新した。配信状態は[新導線の配信記録](SHOPIFY_LINE_FIRST_RELEASE_20261028.md)を参照。

## 顧客導線

1. トップ・商品・カートの「LINEでポイントカードを使う」から `/apps/members` を開く。Shopifyログインは不要。
2. 同じブラウザで会員カードのLIFF endpointを開き、LINE認証、必要なら会員登録と規約同意を行う。購入への利用と、Shopifyログイン時の継続連携に同意する。
3. LINE認証の一回限りコードをショップへ戻す。開始ブラウザのランダムverifierとサーバー側challengeを照合する。会員番号・8文字コードの入力やポーリングは不要。
4. LINE会員と現在のカートを24時間の購入セッションに紐付ける。カート属性 `_agaruke_purchase` にはランダムトークンだけを保存し、LINE UIDを送らない。
5. **ログインして購入**: app proxyのShopify署名付きCustomerを確認できればその場で継続連携。チェックアウトで初めてログインした場合は、注文完了拡張の署名付きsession tokenのsubと、署名済みorders/create通知で得た注文Customer・カート・購入セッションを照合して連携する。
6. **ゲスト購入**: 購入セッションだけを使用し、注文にCustomer IDがあっても継続連携を作らない。次のゲスト購入では再度LINE認証する。
7. 支払い完了webhookで、カート・作成時刻・購入セッションを照合し、一注文100ptを冪等付与する。注文完了画面の表示自体では付与しない。

## 認証と注文の境界

- LINE APIでaccess tokenのchannel・有効期限・本人を確認する。LINE認証コードはLINEブラウザだけへ返し、開始ブラウザからポーリングで取得できない。共有された認証URLだけで第三者がカードを奪えない。
- callbackコードはURL fragmentから即時除去する。開始時のverifierが同じブラウザにない場合は再認証を案内する。PCからスマートフォンで認証するQR方式は今回含めない。
- Shopify app proxyは公式authenticate.public.appProxyで署名検証し、shop・timestampも照合する。ログイン判定が空の場合にメールやLiquid値で推測しない。
- 注文完了拡張は公式authenticate.public.checkoutでJWTを検証し、aud/dest/subを照合する。ブラウザからの注文IDだけを信頼せず、署名済み注文通知のCustomer、カート、購入トークンと一致させる。通知到着前は手動の「再確認」で再試行する。定期ポーリングは追加しない。
- 顧客・会員の一対一対応をTransactionで確認し、既存連携の付替えを拒否する。
- `SHOPIFY_LINE_FIRST_ENABLED=true`では、購入セッションのない注文をCustomer IDだけで付与しない。ゲストのメール入力を認証と誤認しない。
- 購入セッションは一注文のみで使用できる。注文作成が24時間内なら支払い通知の遅延を許容する。二重通知・並行処理・取消先行は注文台帳で制御する。

## クーポン

| 消費ポイント | 商品小計の最低額 | 値引き |
| ---: | ---: | ---: |
| 200pt | 4,000円 | 200円 |
| 500pt | 7,000円 | 500円 |
| 1,000pt | 12,000円 | 1,000円 |

交換時に残高から減算し、3か月有効のEC専用券を作る。店頭/Mobile券とは別管理。要求IDによる冪等交換、pending発行の再開、総利用1回、他割引と併用不可は維持する。LINE再認証後も同じ会員の未使用EC券を再表示する。

ゲストでも使えるよう、新導線の券はCustomer制限を付けず、高エントロピーの一回限りコードとする。これは**コード所持者が利用できる方式**であり、Shopifyがカート/LINE本人に限定して値引きを判定する方式ではない。コードや適用URLを他人へ共有すると、その人が先に使えるため、共有しない案内を表示する。カート属性だけで割引の本人限定を保証するとは扱わない。

## 返金・試験モード

取消/全額返金で100ptを一度だけ取消。一部返金は一注文分を維持する。残高不足時は負残高を許容し、累積ランク値は減算しない。使用券はvoidとして保持し、自動返却・再発行はしない。

本番は本人連携の結合試験を先行するため `SHOPIFY_LINK_TEST_ONLY=true` を維持し、交換とpaid/返金処理をアプリ側で停止する。orders/createは連携照合用の最小情報だけを記録する。Shopify顧客ログインとLINE認証の実機試験は本人操作が必要。

既存2サービスとFirestoreを使用し、CPU/メモリ/最大instance、定期Job、Cloud SQLは増やさない。承認済みの利用規模内を前提とする。実配信時には既配信SHAを包含したcleanなremote master、全関連回帰検査、image digest、revision/trafficを照合する。

## ローカル検証

Go全packageのFirestore Emulator `go test -race ./...` / `go vet ./...`、Nodeの認証・クーポン・暗号化テスト、app/両UI拡張の型検査とbuild、Shopify configとUI/Liquid schema検査を実施する。

旧Shopify先行・手動コード方式の履歴は[旧配信記録](SHOPIFY_LINK_RELEASE_20261028.md)に保持する。現行顧客導線では使用しない。

## 連携済み表示（2026-10-28追記）

[表示とチェックアウト対応](SHOPIFY_LINKED_UI_RELEASE_20261028.md)。連携済みでは上部の連携案内とカートの再連携ボタンを隠し、予定pt/所有EC券の案内に切り替える。Basicプランのため、チェックアウトは標準の商品補足欄に注文全体で一度の予定ptを記載する。試験中は0pt/通常100ptと明示し、予定100ptの確約と誤認させない。継続連携済みCustomerの次のカートでは購入セッションを自動準備する。
