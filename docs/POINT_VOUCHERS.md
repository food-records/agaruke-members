# 一度限りのポイント配布：既存シリアル方式

発行は既存の`gas/serial_generator.gs`、受取は既存の`POST /qrcode`とLIFFの`?code=FR...`、QR画像を使う。新しいコード形式・引換APIは設けない。シリアル形式は従来どおり`FR`＋英数字8文字。

## 発行設定

発行シートのA〜D列（枚数・ポイント・`once`/`recurring`・累積対象）は維持する。新たにE列`campaign_id`、F列`expires_at`を任意で指定できる。単発の配布では`once`とし、ランクに加算しない特典はD列を`FALSE`にする。

| 列 | 今回のアンケート配布 | 用途 |
|---|---|---|
| A count | 25 | 個別シリアルの発行枚数 |
| B point | 700 | 回答へのお礼500pt＋配布遅延のお詫び200pt |
| C type | once | 1枚につき1回 |
| D accumulate | FALSE | ランク累積に加算しない |
| E campaign_id | agaruke-2026-survey-500 | 同じ会員の再受取を防ぐ。ID末尾の`500`は旧方式からの内部識別子として維持する。既存のUID限定特典と同じIDにすることで、そちらの受取履歴とも重複しない |
| F expires_at | 2026-11-24T23:59:00+09:00 | 受取期限 |

本番のScript Propertiesで`FIREBASE_PROJECT_ID=food-records-prod`、`ORGANIZATION_UUID=35095fe0-1efc-40ff-bd13-9720c6d09e0f`、LIFF IDと認証設定が対象環境に合うことを発行前に照合する。既存のシートへGASを反映する作業と発行操作はまだ行っていない。1行400枚まで。既存コードとの衝突・上書きはFirestoreの作成前提条件で拒否する。衝突時は発行をやり直す。

## 引換と保護

LINE認証で特定した会員の登録・同意を確認する。1枚限りのシリアル文書、会員残高、ポイント履歴は単一のFirestore Transactionで更新し、同時に開いても1回だけ加算する。`campaign_id`があれば、そのIDのポイント履歴も確認して1会員1回に制限する。期限を過ぎたコードは拒否する。既存のテスト用`FR1234567890`も本番APIでは通常の1回限りとして扱う。

コードは持参人が使える引換券であり、転送・漏洩した場合は先着で使われ得る。UIDが変わっても引き換えられるが、元のアンケート回答者本人かどうかはコードだけでは証明できない。配布コード・対応表はGitや公開ページに載せない。既存GASのQR画像は外部のQuickChartへURLを渡すため、個別コードも同サービスへ送られる。外部送信を避けたい場合はQR生成方法を別途変更する。

## 今回の配布案（2026-11-01）

- 対象は実回答者25人。テストUIDは除く。各人に700ptの個別シリアルを1件ずつ渡す。特典はランク累積の対象外。
- LINEで連絡できる回答者へ個別送信し、ブロック等で届かない回答者には以前決めたメール経路を使う。送付先と配布コードの対応表は非公開で管理する。
- 受取期限は既定の2026-11-24 23:59 JSTを仮置き。発行・送信前に確認する。
- 旧UID限定キャンペーンはテストUIDのみ有効で、実回答者25人の対象文書は未登録。新シリアルと同じキャンペーンIDで履歴を照合する。テストUIDにはすでに旧方式の500pt受取履歴があるため、配布対象に入れない。
