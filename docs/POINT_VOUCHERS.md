# 使い切りポイント引換券

UIDに依存せず、受け取ったコードをLINE認証済みの会員が1回だけ引き換える。コードは32バイトの暗号学的乱数をURL-safe形式にした`PV_...`。FirestoreにはコードのSHA-256ハッシュだけを保存し、原文と配布URLは権限制限付きのGit管理外TSVにのみ出力する。

## 発行と引換

`members-api`で以下を実行する。最初は`--apply`なしで件数・期限を確認し、実発行時に`--apply`を付ける。`--activate`を省略すると受け取れない状態で作成する。発行後の有効化は管理者が本番設定を確認して別途行う。

```sh
go run ./cmd/point-voucher-issue \
  --project=food-records-prod \
  --campaign=campaign-id \
  --count=25 --points=500 \
  --expires=2026-11-24T23:59:00+09:00 \
  --output=/private/path/vouchers.tsv \
  --apply
```

一度の発行上限は400件。既存キャンペーンIDと既存出力ファイルは上書きしない。発行元にはFirestore書込権限が必要。出力TSVのURLを個別送信するかQRに変換する。送信先との対応表は配布者が別途管理し、Gitには登録しない。

LIFFの`?voucher=PV_...`または同URLのQRを開くと、必要に応じて会員登録・規約同意を行った後、`POST /members/point-vouchers/claim`へコードを送る。APIはLINEアクセストークンからUIDを検証し、引換券、キャンペーン、会員、キャンペーン単位のポイント履歴を同一Firestore Transactionで検査・更新する。ポイントは残高へ加算し、累積ランクには加算しない。期限切れ、停止、使用済み、同キャンペーン受取済みは拒否する。既存アンケート特典のポイント履歴と同じキャンペーンIDを使えば、旧方式で受け取った会員への再付与も防ぐ。

## 配布上の注意

コードは持参人が使える引換券であり、転送・漏洩すると**最初に引き換えた人**が受け取る。UID変更には対応できるが、元の回答者本人かどうかをコードだけで証明できない。配布前に発行件数、送付先、キャンペーンID、期限、既配布分の有無を確認する。コードを公開ページ、共通画像、公開リポジトリ、ログに載せない。引換コードのQR画像を外部生成サービスへ送る場合も、コードを第三者へ渡すことになるため取り扱いに注意する。

既存の`/qrcode`向け`FR...`シリアルと、テスト用に有効化したUID限定アンケート特典は残る。今回の実回答者25人向けコードは未発行・未送信であり、切替時に対象と旧方式の設定を再確認する。
